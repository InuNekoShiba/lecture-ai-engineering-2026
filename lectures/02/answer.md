- 学習後に残った失敗と、その型（根拠なしの質問に断定した / 根拠ありの質問に確認要求で逃げた / 形式の崩れ）：「成績はいつ出ますか」に対し、成績発表日の情報がFAQにないにもかかわらず、課題の提出期限を答え、`needs_review: false` とした。根拠のない質問に別項目の情報を使って答えることで確認不要と判断した例である。また、「オフィスアワーは事前予約が必要ですか」に対し、予約の要否ではなくオフィスアワーの曜日・時間を答え、`needs_review: false` とした。こちらも根拠のない質問に別項目の情報を使った例である。

## 宿題

- 取り組んだレベル：基礎
- 変えた設定やデータ： `CONFIG`の`num_train_epochs`を20から10に変更した。
- 結果（比較表や数字）：
  | 項目 | 演習：20エポック | 宿題：10エポック |
  | --- | ---: | ---: |
  | 学習ステップ数 | 40 | 20 |
  | 学習時間 | 233秒 | 116秒 |
  | 最後に表示されたTraining Loss | 0.013822 | 0.097660 |
  | 学習後の`format_rate` | 100%（21/21問） | 100%（21/21問） |
  | 学習後の`content_rate` | 90.5%（19/21問） | 76.2%（16/21問） |

  - 今回の実行では、10エポックでも形式遵守率は100%だったが、内容正解率は20エポックより低かった。学習時間は約半分になり、最後に表示されたTraining Lossは高かった。10エポックでは、FAQにない質問に対して`needs_review: true`と判断できても、回答文に無関係な情報や不自然な文が混ざる例があった。各条件1回ずつ、21問での比較なので、この結果だけでエポック数と性能の一般的な関係は断定できない。また、総ステップ数が変わるため、学習率の変化スケジュールも同じではない。

- ファインチューニングが向く場面・向かない場面についての考察：回答形式や定型的な振る舞いをモデルに身につけさせたい場面には向いていると考える。今回も、学習後は指定されたJSON形式を全21問で守れた。一方、更新頻度の高い情報や、根拠の正確な確認が必要な情報を、学習済みの知識だけで回答する用途には注意が必要であると思われる。今回も、FAQに根拠のない質問への誤回答が残った。そのような用途では、最新資料を検索して入力に渡す方法や、人による確認を組み合わせることが有効だと考える。
